MenuMind: проверка настоящей LLM и сравнение промптов¶

Это выполненный эксперимент с gpt-5.6-luna, а не демонстрация шаблонов. 32 авторских примера (16 блюд × RU/KK), два промпта, 64 первичных запроса и 8 попыток перегенерации. Отдельно сохранены живые проверки сайта и API.

Воспроизводимость: Restart Kernel → Run All воспроизводит очистку, таблицы, проверки и графики из сохранённых ответов без ключа и платных запросов. Снимок входов и результатов встроен в Notebook; соседние файлы, если присутствуют, должны совпадать по SHA-256. Для нового живого эксперимента нужны Node.js, ключ в .env и скрипты из experiments/llm — команды приведены в конце.

RQ1: уменьшает ли подробный промпт нарушения ограничений? RQ2: как меняются время и токены? RQ3: где остаются ошибки при нехватке фактов, перегенерации и переводе? RQ4: получает ли браузер именно текст провайдера?

Небольшой искусственный acceptance-набор не является случайной выборкой ресторанов. Проверка смысла выполнена Codex и обозначена отдельно; независимой человеческой оценки и проверки носителем казахского языка нет.

4. Промпты, входы и наблюдаемые результаты¶

Простой промпт просит привлекательное описание и JSON, передаёт те же блюдо, язык, тон, ограничения и предыдущий ответ. Подробный — настоящий промпт сервера: только заданные факты, без обещаний пользы, превосходных степеней и выдуманного состава, с пояснением тона. Оба возвращают 4 канала и дополнительный вариант. Выбор модели, JSON-режим, reasoning effort и таймаут одинаковые.

X: поля блюда, язык, тон, лимит и версия промпта. Наблюдаемые y: принятый или отклонённый ответ, длина, задержка, токены и отдельная качественная оценка. Сырые ответы, включая отклонённые сервером, хранятся полностью; это позволяет увидеть ошибки, которые иначе скрыла бы валидация.

Токены взяты из usage реального ответа, а не оценены по длине текста. Поля prompt_tokens, completion_tokens, total_tokens описаны в официальной API-документации. Лимит 250 считается с пробелами. 6. Качественная проверка, язык и тон¶

Codex прочитал сырые ответы для всех 72 попыток, включая отклонённые. Оценка pass: не найдено неподтверждённого факта; review: неоднозначная формулировка; fail: конкретное неподтверждённое утверждение. У подробного промпта обнаружены «лёгкий» салат, подразумеваемая последовательность приготовления и «небольшое количество соли» без заданного количества. Он часто выдаёт только название при нехватке данных: это безопаснее догадки, но язык и тон такого короткого ответа оценить невозможно. Запрошенные тона нередко сводятся к одному нейтральному стилю. Простые промпты добавляют состав и сенсорные свойства.

Для двух блюд каждой части (с составом и без), на обоих языках, передавался предыдущий результат. Сравнивается точный текст Яндекс Еды; это минимальная проверка изменения, а не мера смыслового разнообразия.

Браузерная проверка использует собранный фронтенд и настоящий маршрут Express. Наблюдатель сохраняет ответ fetch, не заменяя его. Проверены ID ответа, токены, совпадение всех четырёх текстов с API и видимого текста карточки. Первый браузерный запуск успешно проверил три живых ответа, затем остановился из-за неверного селектора уведомления в тесте (alert вместо status). Этот результат сохранён; отдельно повторены только проверки ошибок с исправленным селектором, без новых платных запросов.

Недоступность и таймаут воспроизведены контролируемым локальным HTTP-сервером. Эти искусственные сбои не считаются живыми ответами LLM. Сайт показывает ошибку, а новая генерация и шаблонная подмена не появляются.

8. Итог по ТЗ и ограничения вывода¶

  • Настоящая модель → сайт: подтверждено для трёх живых браузерных запросов.
  • RU/KK: развёрнутые ответы и перевод RU→KK получены; для названия без текста язык не оценивается. Проверка носителем казахского остаётся необходимой.
  • Длина: новые настройки всех каналов — 250. Проверены 250 и явный лимит 60. Сохранённые настройки существующих ресторанов не переписывались.
  • Факты: подробный промпт заметно осторожнее, но полного соответствия нет: обнаружены неподтверждённые свойства и количество соли. Серверный словарь неполон.
  • Перегенерация: 6 из 8 попыток дали другой текст. Два повтора KK отклонены с понятной ошибкой; требование «всегда другой готовый вариант» не выполнено.
  • Тон: запрет явных обещаний пользы и превосходных степеней соблюдён в прочитанных подробных ответах; различимость трёх тонов не подтверждена, стиль часто одинаков.
  • Ошибки: HTTP 503 провайдера и таймаут превращаются в понятные сообщения, без подмены результатом шаблона. Проверка сбоя выполнена fault injection.
  • 10 секунд: наблюдаемое время всех вызовов и трёх отображений меньше 10 секунд. Это результат малой последовательной выборки, не нагрузочный SLA. Таймаут ограничивает ожидание, но не гарантирует успешный ответ под нагрузкой.

Требуется редакторская оценка RU/KK, более точная проверка фактов и работа с перегенерацией коротких описаний. Не подгоняем эти исправления по финальной выборке: следующий вариант требует нового holdout. Независимые единицы здесь — блюда, а не пять текстов одного ответа и не два перевода одного блюда.

9. Как повторить живой эксперимент¶

Полный код находится в репозитории, в experiments/llm. Node запускается из корня приложения, где лежит .env. Секреты не записываются в Notebook или журналы. Настройки: LLM_PROVIDER=openai-compatible, LLM_MODEL=gpt-5.6-luna, LLM_REASONING_EFFORT=none, LLM_TIMEOUT_MS=8500, свой LLM_API_KEY.

  1. Установить зависимости: npm ci; Python — из experiments/llm/requirements.txt.
  2. Сохранить существующую папку experiments/llm/results под другим именем: скрипты намеренно отказываются перезаписывать измерения.
  3. node experiments/llm/run.mjs smoke
  4. node experiments/llm/run.mjs dev
  5. python experiments/llm/freeze.py
  6. node experiments/llm/run.mjs final
  7. npm run build, затем node experiments/llm/browser.mjs и node experiments/llm/browser.mjs --faults-only и node experiments/llm/contract.mjs.
  8. Качественную разметку сделать заново: старые оценки действуют только для старых SHA-256 ответов. Не переносить выводы по ID блюда на новые ответы.

Этот Notebook фиксирует конкретный выполненный прогон. Для нового прогона нужно обновить разметку и собрать новый Notebook, сохранив старые материалы. Текст и задержка не обязаны повторяться побайтно: генерация стохастична, сеть и версия модели могут меняться. Нагрузка здесь последовательная, регион и кэш провайдера не контролировались. Полные raw JSON позволяют независимо пересчитать все численные показатели. Тарифы не зафиксированы; токены не выдаются за стоимость.
