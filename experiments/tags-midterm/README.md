# MenuMind: эксперимент с тегами блюд

В этой работе модель определяет десять тегов по названию и составу рецепта.
Эксперимент нужен для подготовки персонализации описаний в MenuMind. Сам сервис
генерирует тексты через внешнюю LLM; требования к нему находятся в `assignment.docx`
(копия `10 (3).docx`).

## Что открыть

Для просмотра результатов удобнее начать с `MenuMind_report.pdf` или
`MenuMind_tags.html`. В отчёте две страницы, в HTML есть весь анализ с кодом,
таблицами и девятью графиками.

Презентация находится в `MenuMind_presentation.pptx`, её копия для просмотра
в `MenuMind_presentation.pdf`. К семи слайдам добавлены заметки докладчика;
тот же текст вынесен в `speaker_notes.txt`. Отчёт можно редактировать в DOCX.

Для запуска исследования нужен `MenuMind_tags.ipynb`. Исходный архив лежит в
`data/raw/epirecipes-v2.zip`, информация об источнике и контрольные суммы
в `source_manifest.json`. Словарь из десяти целевых тегов сохранён в
`tag_catalog.json`. Обученная модель находится в
`artifacts/models/tag_classifier.joblib`, метрики и таблицы в `artifacts/`.

## Как повторить эксперимент

Нужен Python 3.10 или новее. Из этой папки выполните:

```sh
python -m pip install -r requirements.txt
python execute.py
```

Можно открыть notebook в Jupyter и выбрать Restart Kernel → Run All. Код использует
архив рядом с notebook, а если архива нет, загружает вторую версию датасета с Kaggle
и проверяет SHA-256. Пути определяются автоматически. Интернет нужен для установки
библиотек и загрузки отсутствующего архива; API-ключ и GPU не требуются.

Пример использования сохранённой модели:

```sh
python predict.py --title "Chicken with rice" --ingredients "chicken" "rice"
```

Модель обучалась на английском корпусе. Её предсказания можно использовать для
исследования категорий, но нельзя переносить в описание как подтверждённые факты
о составе блюда.

Для проверки запуска вне репозитория предусмотрен `python execute.py --portable`.
Команда копирует notebook и архив в отдельную папку, выполняет все ячейки и сравнивает
метрики. Результат записывается в `artifacts/portable_verification.json`. Такой запуск
проверен локально; запуск в Google Colab отдельно не проверялся.

Если меняется структура notebook, `build_notebook.py` пересобирает его без результатов
выполнения, после чего нужно снова запустить `execute.py`. Команда
`python build_documents.py` обновляет отчёт и слайды по `artifacts/metrics.json`.
Текст отчёта и заметок хранится в `document_text.py`.

## Результат

Обучение проводилось на 12 383 рецептах, подбор параметров на 2 649, итоговая
проверка на 2 651. Для модели с названием и составом выбраны C=2 и порог 0,35.
Категории издателя использовались только как целевые метки.

| Метод | micro-F1 | macro-F1 |
|---|---:|---:|
| Название + состав | 0,591 | 0,586 |
| Только название | 0,614 | 0,657 |
| Частоты train | 0,240 | 0,032 |
| Словарь | 0,492 | 0,619 |

Обученная модель опередила частотный метод. При этом добавление состава не помогло:
модель только по названию получила более высокие значения обеих F1-метрик. По macro-F1
словарь тоже оказался сильнее полной модели. Возможные причины и ошибки отдельных
тегов разобраны в notebook. Параметры по итоговому тесту не менялись.

## Как это связано с приложением

В API упоминания в конкретном описании извлекает серверный словарь. Для каждого
тега сохраняется фрагмент текста и основание в исходной карточке. LinUCB получает
эти признаки вместе с предпочтениями гостя и историей показов. Подробности полей,
запросов и учёта реакций описаны в `integration.txt`.

Данных о реальных показах и заказах пока нет. Следующая проверка должна включать
новые описания RU/KK с ручной разметкой, а затем сравнение персонализированной
и контрольной выдачи.

Код сервиса, Swagger и инструкция по подключению LLM находятся в основном
репозитории MenuMind. Там же в `experiments/llm-v2/` сохранены предыдущие результаты
генерации RU/KK, измерения задержки и расчёт стоимости. Они относятся к прежнему
прогону. Исходный эксперимент по тегам не включал новых вызовов LLM;
сами теги рассчитываются без дополнительного запроса к провайдеру.
08.10.2026 выполнена дополнительная проверка четырьмя живыми запросами RU/KK.
Её результаты и проверка требований собраны в [project-audit.txt](project-audit.txt)
и `audit-live-generation.json`. Эти запросы не входят в метрики классификатора.
Приёмка на 30 позициях заказчика и проверка грамматики человеком ещё предстоят.
