# Финальная модель MenuMind

## Выбор и версия

`menumind-lora-1.0.0+2e24ee64a276`: Qwen2.5-0.5B-Instruct + сохранённый LoRA, LR=0.0005. Выбор сделан до test по validation response-token NLL: 0.0011057 против 0.0046048 у LR=0.0002. На прежнем синтетическом test подробный промпт + LoRA прошёл слот-проверки 36/36, подробный промпт — 5/36, простой — 2/36. Это лучшая из исследованных конфигураций по этому протоколу, не утверждение о лучшей доступной LLM.

`final_model.json` фиксирует модель, контракт и SHA-256 файлов. База и токенизатор: `Qwen/Qwen2.5-0.5B-Instruct`, revision `7ae557604adf67be50417f59c2c2f167def9a775`. Адаптер: `artifacts/adapters/lr-0.0005`; SHA-256 весов: `2e24ee64a276cc99904bf4d2b12892a6b3710b2d7a8bfeaa089a69aeb4d27a61`.

Загрузчик проверяет веса, конфигурацию адаптера, config, selection, common.py и словарь. Использует `is_trainable=False`, `eval()`, замороженные параметры и `torch.inference_mode()`. Greedy decoding, максимум 128 новых токенов. Автоматически выбирается CUDA при наличии, иначе CPU. Веса при inference не меняются.

## Запуск

Все команды из корня репозитория, где находятся server/, frontend/ и experiments/.

В подготовленном окружении Windows:

```powershell
../.venv-lora/Scripts/python.exe experiments/lora-study/serve.py --offline
```

Откройте <http://127.0.0.1:8008>. Модель загружается один раз, затем форма принимает новые техкарты. Одновременно выполняется одна генерация; параллельный запрос получает 503. Проверка состояния доступна во время генерации. Сервис слушает только localhost; это локальная демонстрация.

Новая машина, Python 3.10, CPU:

```powershell
python -m venv ../.venv-lora
../.venv-lora/Scripts/python.exe -m pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cpu
../.venv-lora/Scripts/python.exe -m pip install -r experiments/lora-study/requirements.txt
../.venv-lora/Scripts/python.exe experiments/lora-study/serve.py --device cpu
```

Для NVIDIA используйте CUDA-команду из README эксперимента. Первый запуск без `--offline` загружает базовую модель из Hugging Face; затем можно работать с `--offline`. Отсутствующие адаптеры восстанавливаются из включённого в репозиторий прежнего ZIP. Повреждённые существующие файлы не перезаписываются молча: запуск останавливается с ошибкой хеша. Точное экспериментальное окружение: `artifacts/requirements-lock.txt` (CPU-сборка torch отличается).

CLI:

```powershell
../.venv-lora/Scripts/python.exe experiments/lora-study/infer.py --input experiments/lora-study/examples/new-ru.json --offline
../.venv-lora/Scripts/python.exe experiments/lora-study/infer.py --input experiments/lora-study/examples/new-kk.json --device cpu --offline --output work/answer.json
```

stdout — один JSON; сообщения библиотек идут в stderr. Коды выхода: 0 — проверки пройдены; 3 — ответ модели отклонён; 2 — ошибка входа/валидации/целостности; 1 — модель недоступна. `--example-id` поддерживает старые test-примеры, но не выдаёт их за новые данные.

## Вход

```json
{
  "language": "ru",
  "recipe": {
    "name": "Индейка с булгуром",
    "ingredients": ["индейка", "булгур", "морковь"],
    "method": "тушение"
  },
  "channel": "website",
  "tone": "neutral",
  "maxLength": 250
}
```

Обязательны language (ru/kk) и recipe с ровно тремя указанными полями. channel/tone/maxLength необязательны, но принимают только website/neutral/250 — другие режимы не оценивались. Название и метод: 1–120 символов; ингредиенты: 1–12 уникальных строк по 1–80 символов. Пробелы и Unicode NFC нормализуются. Неизвестные поля, управляющие/невидимые символы и неверные типы отвергаются.

JSON: максимум 16 KiB. Полный токенизированный промпт: максимум 384 токена, плюс 128 на ответ в учебном бюджете 512. Длинный вход не обрезается. Поля должны быть на выбранном языке; перевод не является проверенным свойством версии. Здесь ингредиенты и метод обязательны, в отличие от библиотеки рецептов основного сайта. Служебные поля датасета id/target/split во вход не включаются.

## Выход

Ответ содержит `accepted`, `description`, `raw_output`, `scores`, `validation_errors`, `validation_version`, `model_version`, `base_revision`, `adapter_sha256`, `language`, `input_tokens`, `generated_tokens`, `generation_seconds`, `latency_seconds`, `device`, `requires_human_review`.

Если проверка не пройдена, `accepted=false`, `description=null`. Сырой ответ сохраняется для разбора. Подмены шаблоном и обрезки ради прохождения проверок нет. Проверяются JSON-схема, длина, ограниченный диапазон эмодзи, имя блюда, буквальное присутствие всех ингредиентов и метода, известные лишние факты, управляющие символы и исчерпание лимита токенов.

`final-v1` дополняет замороженный scorer: учитывает регистр и уточнения вроде «рис басмати», требует имя блюда и отсутствие управляющих символов. Исторические метрики не пересчитываются по новым правилам. scores — диагностические прокси; accepted учитывает также дополнительные проверки.

`requires_human_review=true` всегда. Словарь и буквальные совпадения не доказывают отсутствие всех галлюцинаций, естественность языка или безопасность блюда.

HTTP: GET /health, GET /model, POST /generate (application/json). Статусы: 200 — принят, 422 — ответ отклонён, 400 — неверный вход, 413 — слишком большой запрос, 415 — неверный Content-Type, 503 — модель занята. Посторонние Host и межсайтовые запросы отвергаются. Публичная авторизация, TLS, очередь и масштабирование не реализованы.

## Измерения и проверка

`benchmark_final.py --offline` выполняет прогрев и три новых примера по три раза. Сохраняет все ответы, время, устройство и хеши входов; проверяет отсутствие совпадения техкарт с прежними split. Это малый последовательный замер, не новый независимый датасет качества.

Замер 9 ноября 2026: RTX 4060 Laptop, bfloat16. Девять запросов, три входа: медиана 1,47 с, среднее 1,56 с, диапазон 1,24–2,00 с. Все девять прошли автоматические проверки. Пиковая выделенная память тензоров CUDA: около 0,95 GiB (не вся память процесса). Инициализация с импортами 6,44 с, внутренний этап загрузки 1,05 с при тёплом файловом кеше. Один CPU-пример KK: 4,35 с, float32, четыре потока. Нет проверки SLA, нагрузки или надёжной оценки p95.

Артефакты: `artifacts/final-benchmark.json`, `final-demo-ru.json`, `final-demo-cpu.json`. Числа относятся к конкретному запуску и могут отличаться на другой машине.

```powershell
../.venv-lora/Scripts/python.exe -m unittest discover -s experiments/lora-study -p "test_*.py"
../.venv-lora/Scripts/python.exe experiments/lora-study/audit_artifacts.py
npm test
npm run build
```

Тесты покрывают некорректный вход, повреждение файлов, неполный ответ, контрольные символы, регистр/уточнения ингредиентов, HTTP-контракт и пустое подключение браузера. Реальные веса проверены на CUDA и CPU; браузер — RU/KK и ширина 390 px.

## Архитектура и дальнейшие улучшения

Финальный путь: JSON/форма → валидация → Qwen + LoRA → проверка ответа → редактор.

Основной сайт: React → Express → API-провайдер или явно обозначенные шаблоны; SQLite хранит данные, LinUCB выбирает варианты. **LoRA пока не подключена вместо четырёхканального провайдера сайта.** Одноканальный адаптер не является проверенной заменой с другими стилями/лимитами.

Данные синтетические и шаблонные. Детерминированный шаблон тоже проходит слот-проверки: эксперимент не доказывает необходимость LLM. Следующие улучшения: реальные редакторские тексты, новый holdout по ресторанам/блюдам, слепая оценка RU/KK носителями, сравнение с шаблоном и API-моделью, затем интеграция, проверка каналов и нагрузочные измерения.
