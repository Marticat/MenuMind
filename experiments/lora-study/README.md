# MenuMind: эксперимент с LoRA

Учебная адаптация открытой LLM для задачи «техкарта → описание блюда» на русском и казахском. Приложение продолжает работать со своим API-провайдером; эксперимент и веса адаптера находятся отдельно.

**Все новые обучающие пары синтетические. Экспертной разметки и проверки казахского носителем языка нет.** Эксперимент измеряет следование формату и воспроизведение заданных фактов, а не коммерческое качество текстов.

## Результаты и материалы

- `REPORT.txt` — результаты, интерпретация, ограничения и ответы для защиты; строится из фактических артефактов.
- `MenuMind_LoRA.ipynb` — выполненный notebook с воспроизводимым анализом сохранённых ответов.
- `artifacts/results.csv` — общая таблица: классический baseline/tuned и три LLM-конфигурации. Пустые поля обозначают неприменимые метрики.
- `artifacts/selection.json` — два запуска обучения, loss по эпохам, выбранный learning rate, количество параметров и доказательство изменения весов.
- `artifacts/predictions-*.jsonl` — полные промпты, сырые ответы, метрики и задержки всех конфигураций на одном test.
- `artifacts/adapters/lr-*/` — реальные LoRA-веса и токенизатор. Большие файлы исключены из Git, но сохраняются локально.
- `artifacts/human_review.csv` — незаполненный лист оценки человеком. Его пустые поля не заменяются автоматическими оценками.
- `artifacts/verification.json`, `freeze.json`, `environment.json`, `requirements-lock.txt` — аудит и воспроизводимость.
- `MenuMind_LoRA_submission.zip` — архив исходников, данных, результатов, выполненного notebook и обоих адаптеров. Базовая Qwen загружается отдельно по закреплённой revision.

## Протокол

`prepare_data.py` создаёт 120 уникальных комбинаций основного ингредиента и дополнения, по две языковые версии: 240 примеров. Целевые описания составлены детерминированно из техкарты. Метка происхождения и `human_reviewed: false` сохранены в каждой строке. Данные не являются реальными заказами или авторскими текстами ресторанов.

Фиксированный split с seed=42: 84/18/18 блюд, или 168/36/36 строк. Обе языковые версии блюда остаются в одной части. В тесте новые комбинации знакомого словаря; шаблон ответа общий. Это ограниченная проверка обобщения, не проверка на новом домене. Старые API-примеры из `llm-v2` не смешиваются с этим экспериментом.

Детерминированный генератор эталонов по построению проходит все слот-проверки набора. Это упражнение показывает реальное обучение адаптера, но не доказывает необходимость LLM или превосходство над шаблоном. Для такого вывода потребуются разнообразные реальные тексты и независимая редакторская оценка.

Сравниваются три конфигурации одной `Qwen/Qwen2.5-0.5B-Instruct`:

1. Исходная модель и короткий промпт.
2. Исходная модель и подробный промпт.
3. Та же модель с LoRA и тем же подробным промптом.

Входы, test, декодирование и метрики одинаковы. Каждая строка обрабатывается один раз, без исправляющих повторных запросов. Ответ — `{"description":"..."}`, один канал `website`, нейтральный тон, 250 символов. Это исследовательский контракт, а не реализация четырёхканального API приложения.

Fine-tuning: AdamW; causal cross-entropy только по токенам ответа, входной промпт и padding исключены из loss; batch=2, accumulation=4, effective batch=8, epochs=3, max sequence=512; LR ∈ {0.0002, 0.0005}; weight decay=0.01; gradient clipping=1.0. Scheduler — постоянный LR. Отдельный запуск для каждого LR с одинаковыми исходными весами и seed. Выбор по минимальной validation response-token NLL после третьей эпохи. Генерация на test начинается после записи выбора и freeze.

LoRA: r=8, alpha=16, dropout=0.05, target modules=`q_proj`, `v_proj`. Основные веса заморожены. Используется bfloat16 при поддержке GPU, без квантования: **это LoRA, не QLoRA**. Точное число обучаемых параметров записывается из реальной модели. PEFT выбран из-за ограничений памяти 8 ГБ и компактного сохраняемого адаптера. Обучение полной модели для сравнительного эксперимента не проводилось.

Transfer learning: готовые языковые и инструктивные представления адаптируются к структуре техкарты и формату описаний. В карточке модели указан русский; поддержку и качество казахского не считаем доказанными. Модель 0.5B выбрана для доступной локальной GPU, а не как установленный лидер качества.

## Метрики

- `json_valid`: ровно один JSON-объект с единственным непустым строковым полем `description`.
- `constraint_pass`: валидная схема, максимум 250 символов, отсутствие эмодзи в проверяемом диапазоне Unicode.
- `ingredient_recall`: доля исходных ингредиентов, найденных буквальными фразами; склонения могут снижать эту оценку.
- `method_match`: найден исходный способ приготовления.
- `known_fact_pass`: валидный ответ без лишних ингредиентов и способов из конечного словаря. **Не является полной проверкой галлюцинаций.**
- `grounded_slot_pass`: выполнены ограничения, присутствуют все ингредиенты и метод, пройдена словарная проверка.

Все метрики показаны совместно и отдельно для RU/KK. Показатели формата не заменяют проверку языка. Bootstrap использует блюда как единицу, сохраняя парность RU/KK; 2000 повторов, seed=42. Он не оценивает вариативность разных training seeds. Задержка — измерение локальной последовательной генерации с первым вызовом; цены API и production throughput не выводятся.

Классический ML пересчитывается по прежним EN split из `tags-midterm`: TF-IDF + One-vs-Rest LogisticRegression. Baseline C=1, threshold=0.5; поиск C ∈ {0.5, 2}, threshold ∈ {0.2, 0.35, 0.5}; выбор по validation micro-F1. Сравниваются micro-F1 и macro-F1, отдельным блоком от генерации. Старый test уже публиковался — это явное дополнение default/tuned, не новый закрытый holdout.

## Запуск

Python 3.10, NVIDIA CUDA GPU. Команды из корня репозитория `MenuMind`, содержащего `server` и `frontend`. Окружение ниже создаётся за пределами репозитория; в данной сессии использовано `../.venv-lora`.

```powershell
python -m venv ../.venv-lora
../.venv-lora/Scripts/python.exe -m pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cu124
../.venv-lora/Scripts/python.exe -m pip install -r experiments/lora-study/requirements.txt
```

Проверка и повторный анализ готовых результатов **без сети и GPU**:

```powershell
../.venv-lora/Scripts/python.exe experiments/lora-study/run.py
```

Новый полный эксперимент с настоящим обучением:

```powershell
../.venv-lora/Scripts/python.exe experiments/lora-study/run.py --train
```

Команда последовательно подготавливает данные, проверяет split/метрики, обучает классический ML, обучает два адаптера, оценивает три конфигурации на test, проверяет артефакты и выполняет notebook. При уже существующем `selection.json` повторное обучение намеренно останавливается: для нового эксперимента скопируйте папку и архивируйте старые артефакты. Первый запуск скачивает примерно 1 ГБ весов, PyTorch занимает ещё несколько ГБ. Платные API не вызываются. Вызов `run.py` без `--train` не изменяет веса.

После `git clone` команды `run.py` и `infer.py` автоматически восстанавливают отсутствующие веса адаптеров и классические split из включённого ZIP, проверяя SHA-256. Уже существующие файлы не перезаписываются. Восстановленные папки исключены из Git; исходная Qwen по-прежнему загружается отдельно при генерации или обучении. `.gitattributes` сохраняет точные байты файлов эксперимента для проверки хешей на Windows и Linux.

При прерывании только этапа генерации после завершённого обучения:

```powershell
../.venv-lora/Scripts/python.exe experiments/lora-study/train.py --evaluate-only
../.venv-lora/Scripts/python.exe experiments/lora-study/run.py
```

`--evaluate-only` проверяет хеши замороженного кода и конфигурации, использует уже выбранный адаптер. Не используйте test для изменения LR, промптов или датасета. Если после просмотра test изменена методика, создайте новый независимый test и новый study.

Проверить сохранённый адаптер на одном примере:

```powershell
../.venv-lora/Scripts/python.exe experiments/lora-study/infer.py --example-id dish-00-03-ru
```

Для своей техкарты используйте `--input путь/к/карточке.json`; схема входа соответствует строкам `dataset/test.jsonl`. Вывод включает сырой ответ и флаг необходимости проверки человеком. Веса при этом не меняются.

Точная revision модели фиксируется в `config.json`, установленное окружение — в `artifacts/requirements-lock.txt`. Seed и параметры фиксированы; побитовая идентичность на других GPU/версиях драйверов не гарантируется. `audit_artifacts.py` независимо пересчитывает метрики по сырым ответам. Notebook требует всю папку эксперимента, не является одним автономным файлом.

Архив создаётся командой `python experiments/lora-study/package_submission.py`. Он включает копии шести исходных X/y split классического эксперимента в `classical-data/` и их манифест происхождения. После распаковки запускайте `python lora-study/run.py` из папки распаковки, используя окружение с зависимостями из `lora-study/requirements.txt`. Вне основного репозитория `classical.py` автоматически использует вложенные `classical-data/`.
